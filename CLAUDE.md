# wikiknit

Rust CLI + Claude Code plugin that lints wikilinks in Markdown vaults that agents keep as memory. User docs: `README.md`.

- Layout: `src/` (lib + `main.rs` CLI; `init.rs` sets a vault up: config + git hooks; `snippet.rs` + `snippet.md` the agent instructions that `wikiknit snippet` prints), `docs/agent-install.md` (setup steps written for an agent; keep it true to `init`/`snippet`), `tests/*.rs` (end-to-end: the real binary on temp vaults or `tests/fixtures/<vault>/`; `tests/lean.rs` runs real git, including a real pre-commit hook), `plugin/` (Claude Code plugin: the `link` skill and one `PostToolUse` hook, `wikiknit hook read`), `.claude-plugin/marketplace.json` (this repo as a marketplace).
- Checks before commit: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`. After plugin edits: `claude plugin validate ./plugin` and `claude plugin validate .`.
- Tests run the real binary on fixture vaults. No mocks. New rule -> new fixture case.
- Scope: deterministic checks that find real defects in an agent's vault, or stay quiet. Search, context packs, link suggestions, and the Claude Code commit gate were removed in 0.7 after an evaluation showed they cost more than they helped (Claude Code's own Grep/Read did as well); add a feature only with measured evidence that it helps an agent.
- `--changed`/`--staged` compare with git HEAD and report only introduced findings (`git.rs` exports HEAD or the index to a temp dir). Inside a git hook, `GIT_DIR`/`GIT_INDEX_FILE` name the index being committed: keep them (made absolute) for the vault's repo, and clear them for other repos (`drift`). Git calls run with the repo's programs turned off (fsmonitor, hooks, pager, signatures, network); they only read (`--staged` writes its tree into a temporary object store). A hook's relative `GIT_*` values: try the cwd reading, then the top reading, and keep the first whose paths exist; a hook for another repository (submodule superproject, outer repo) checks nothing.
- The core stays agent-agnostic. Anything Claude-specific lives in `plugin/`, except `hook.rs` (the hidden `hook read` the plugin's hook runs: Claude Code's hook JSON in, `additionalContext` out). `hook read` never blocks: no finding or any failure prints nothing and exits 0; every other `hook <name>` (the 0.6 hooks old plugin caches still run) is a no-op. The snippet names no agent's tool; it goes into whichever instruction file the agent reads.
- `init` never overwrites: an existing `wikiknit.toml` is kept; it edits only hooks whose second line is its marker; it writes no hook in a `core.hooksPath` from global/system config or outside the repository. It writes only what the vault shows (no guessed rules). Its git calls read the user's real config (`init.rs` `git_in`), unlike `git.rs`, which turns hooks off.
- Install locally: `cargo install --path . --locked` (to `~/.cargo/bin`).
- Release: bump `version` in `Cargo.toml` and `plugin/.claude-plugin/plugin.json`, commit `vX.Y.Z: ...` on `main`, push, then push tag `vX.Y.Z` (`.github/workflows/release.yml` checks it matches `Cargo.toml`, builds the binaries, and publishes the GitHub release). Then `cargo publish` (Victor's crates.io login). Asset names `wikiknit-vX.Y.Z-<target>.tar.gz` are shared by `install.sh` and `[package.metadata.binstall]`: change all three together.
